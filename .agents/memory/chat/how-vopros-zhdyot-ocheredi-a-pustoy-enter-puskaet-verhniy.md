# Вопрос поверх хода ждёт в очереди, пустой Enter пускает верхний

Очередь вопросов живёт в панели (`apps/web/app/routes/[company]/sessions/[session]/page.tsx`),
а не в API. Вопрос уходит в API только тогда, когда его время пришло, поэтому хвост
очереди не попадает в ленту: строк, которых агент не получил, в `ctx.messages` нет.

## Как это работает

- Агент занят — вопрос ложится в очередь и виден над полем ввода, а не в ленте.
- Агент свободен — вопрос уходит в API сразу.
- Ход кончился (`done`, `failed`) — очередь идёт сама: верхний уходит без человека.
- Пустой Enter при непустой очереди — верхний уходит сейчас. Это один запрос
  `POST /v1/companies/:id/conversations/:conversationId/messages` с `interrupt: true`:
  он останавливает идущий ход и встаёт первым. Пять вопросов в очереди — пять нажатий.

Очередь принадлежит чату: открыли другой — она пуста. Перезагрузку страницы очередь не
переживает: это ожидание, а не запись.

## Признак «агент занят»

Идущий ход — тот, у которого нет конца (`endedAt === null`). Виден он из двух мест:

- **журнал страницы** (`log.state.work`) — ход, начатый этой страницей;
- **лента сервера** (`messages.at(-1).raw`) — страница, зашедшая посреди хода: её журнал
  пуст, а запись идущего ответа уже лежит в базе.

Одного журнала мало: обновлённая посреди хода страница считала бы агента свободным и
отправила бы вопрос сразу в обход очереди.

## Что помнить

- Остановку держит `running` в `apps/api/src/agent.ts`: ход у чата один, поэтому запись
  одна, и `stopTurn` бьёт по нему.
- Ход без прерывания остаётся в очереди API (`pending` там же): панель ждёт конца хода,
  а чужая панель или бот свою очередь всё равно получат.
- Очередь не переживает перезагрузку, поэтому застрявшую («агент будто бы занят» после
  падения API) страницу лечит пустой Enter: он пускает верхний вопрос в обход.
