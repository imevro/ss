# Лента собирается переигрыванием журнала

Состояние ленты не хранится. Хранится **журнал событий**: `localStorage`, ключ
`ss.chat.<номер чата>`. Лента и строка хода работы — это результат прохода по
журналу (`fold` в `apps/web/app/lib/chat-state.ts`).

Почему так, а не «хранить готовые реплики»:

- восстановленный чат не отличается от свежего: тот же проход, те же события;
- разметку не надо хранить и потом сверять — она выводится;
- нового вида события достаточно один раз описать в одном месте.

## Правила

- Событие сперва ложится в журнал, состояние читается из журнала. Второго пути
  сборки нет.
- Готовые реплики с сервера кладутся впереди переигранных. Лишние переигранные
  отсеиваются **по номеру записи**: запись отвечает номером (`messageId`), событие
  журнала его помнит. Ни текст, ни счёт реплик для этого не годятся: журнал не
  всегда помнит всю ленту, и счёт сбивается — тогда свежий вопрос пропадал бы
  с экрана.
- Готовые реплики несут свой ход работы из записи (сырое поле `raw`), идущая —
  живой ход из журнала. Поэтому строка работы одинакова до и после обновления,
  и её не надо привязывать к ответу задним числом.
- Журнал ограничен 2000 записей: старое уходит, лента читается с конца.
- Ядро (`fold`, `stateOf`) — чистое: ни окна, ни хранилища.
- Сервер отдаёт тело шрифтом системы, а не привозным: подвожу `--font-sans` к
  `-apple-system` и убираю `@fontsource-variable/inter`.
