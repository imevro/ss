# Поля организаций сверяются с плагином по именам

Плагин `organization` находит свою схему в нашем объекте таблиц по ИМЕНАМ: имя таблицы
(`organization`, `member`, `invitation`) и имена полей должны быть его (`organizationId`,
`userId`, `createdAt`, `inviterId`). Имя колонки в базе при этом свободно — оно задаётся
первым доводом (`text('organization_id')`).

Из этого следует:

- переименовывать таблицу или поле «по-своему» нельзя — плагин перестанет видеть данные;
- у организации НЕТ поля `updatedAt` (в 1.7.7), а у членства нет `status` — лишние поля
  допустимы, только если они необязательные или со значением по умолчанию, иначе вставка
  плагина падает;
- `organization.metadata` объявлено строкой, и адаптер сам делает из значения JSON-строку.
  Класть туда наш `jsonb`-столбец нельзя: значение закодируется дважды. Столбец — текстовый,
  читаем `JSON.parse`.

Расхождение видно сразу: чтение через плагин бросает несоответствие схемы, а `drizzle-kit push`
печатает изменения.
