# Миграции отстают от схемы, пока разработка накатывает схему прямо

В разработке схема базы накатывается **прямо**, командой `drizzle push`, а файлы
миграций делают только к выпуску. Обычные правки схемы поэтому миграций не
порождают: файлы в `packages/db/drizzle` обновляются редко, а схема уезжает
вперёд. Разница незаметна, пока работаешь на уже накатанной базе — и всплывает
только на чистой.

Чем опасно: на чистой базе, поднятой с нуля по миграциям, нет того, что рабочая
база получила через push. В этой сессии так пропали последовательность
`agent_session_number` (её требует создание чата) и два уникальных индекса
`agent_sessions` (`agent_sessions_gentic_key`,
`agent_sessions_company_conversation`). Приложение на такой базе падает на
создании чата, а уникальность `agent_sessions` не защищена.

Проверка — на чистой базе, а не на рабочей:

1. создать пустую базу;
2. накатить миграции (`bun run db:migrate`);
3. сверить столбцы и индексы с рабочей базой (например, `\d agent_sessions`
   в обеих, или сравнение `information_schema`).

Починка — сгенерировать недостающее из схемы: `bun run db:generate` в корне
дописывает разницу новой миграцией. Убедиться, что в ней есть последовательность
и оба уникальных индекса, и только после этого считать миграции готовыми
к выпуску.
