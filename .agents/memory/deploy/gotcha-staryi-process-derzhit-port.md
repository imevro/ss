# Порт держит старый процесс — проверка врёт

Служба разработки поднимается рукой и живёт между сессиями. Если порт `8787` уже занят вчерашним
процессом, новая копия падает с `EADDRINUSE`, а `curl localhost:8787` **отвечает старым кодом**.
Проверка выглядит успешной и подтверждает то, чего в дереве уже нет.

Как ловить:

```bash
lsof -nP -iTCP:8787 -sTCP:LISTEN     # кто держит порт и с каких пор
```

Если команда показывает не тот процесс, который только что запущен, — сначала остановить старый,
дождаться освобождения порта, потом запускать свой. Готовность «порт открыт» этого не различает:
порт может быть открыт чужим процессом.

- Проверка вырезанного маршрута — только после своего запуска: `curl -o /dev/null -w '%{http_code}'`
  должен дать 404, а не 200 от старого кода.
