# Как выпускается версия

Сборочного конвейера в репозитории нет: каталога `.github/workflows` нет совсем.
Выпуск делают руками, и он весь состоит из трёх шагов:

1. слить работу в `master`;
2. поставить метку версии;
3. сделать выпуск на GitHub.

Отдельного развёртывания тоже нет. Выпуск — это и есть выдача: код в `master`
плюс метка и выпуск. Сборка на стороне GitHub ничего не проверяет, потому что
её нет.

## Как идёт работа до выпуска

Работа идёт в копии `.worktrees/mvp-0.1` (ветка `iso/mvp-0.1`), а в `master`
вливается одним коммитом. Вливание идёт в главном каталоге.

Что помнить при вливании:

- Общие привязанные к сборке файлы правят обе стороны. В этой сессии вливание
  столкнулось в `package.json`, `packages/db/drizzle.config.ts` и
  `packages/db/package.json`: вторая сессия параллельно правила те же места.
  Столкновение решили в пользу ветки — она свежее.
- Память проекта (`.agents/memory`) до этой сессии в git не лежала. Её перенесли
  в ветку, и в git она попала первым выпуском. Дальше она часть репозитория.
