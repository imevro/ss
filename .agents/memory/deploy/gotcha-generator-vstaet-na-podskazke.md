# `db:generate` встаёт на подсказке о переименовании старых таблиц

Генератор миграций сравнивает схему со снимком (`packages/db/drizzle/meta/*.json`),
а в снимках до сих пор живут таблицы, которых в схеме нет: `companies`,
`memberships`, `invites`, `chat_bindings`, `audit_log`, `flags`. Поэтому перед
записью файла drizzle-kit спрашивает человека: «`apikey` создать или переименовать
из одной из них?» — и без ответа файла не пишет.

Как ловить:

- не терминал — генератор отказывается словами «Interactive prompts require a TTY
  terminal» (`bin.cjs:1450`), и это видно, когда команда идёт через конвейер;
- терминал есть — он показывает список переименований
  (`promptNamedWithSchemasConflict`, `bin.cjs:32794`) и ждёт выбора; ответ на каждый
  новый вид таблицы — «create table», иначе генератор запишет переименование
  старых таблиц в новые.

То есть `bun run db:generate` — команда, которой нужен живой человек, а не строка
в конвейере. Самый порядок починки отставших миграций описан в
`gotcha-migracii-otstayut-ot-shemy.md`.
