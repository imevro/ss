# ss — МВП 0.1 (план, редакция 2)

> Цель: зайти на `ss.erodionov.com`, войти, пройти онбординг, увидеть свои беседы в нашей панели,
> поговорить с агентом в табе, получить отчёт по проектам из своей базы и получить сгенерированный
> канбан по адресу. Пока — на локальной машине, домен подключаем в конце.

## 1. Сквозной путь

1. Онбординг: детерминированный чат задаёт четыре вопроса; на «чем занимается» показывает предложение по таблицам; я подтверждаю.
2. Выписывается моя база: своя база, три роли, схемы `app` и `ctx`, таблицы из предложения.
3. Онбординг говорит: добавь `@mladmkawdmwkaldmnawss_bot` в рабочий чат, дай админку. Сообщения падают в мою базу.
4. Экран «Беседы»: слева список, справа лента. **Телеграмные чаты и сессии агента — один и тот же экран, разные источники.** Телеграм — входящий поток, сессия — с полем ввода и живым ответом.
5. Пишу агенту «дай статус по проектам» → он читает мою базу **на чтение** → текстовый отчёт.
6. Пишу «собери канбан по проектам» → агент собирает миниапп, он публикуется спрайтом, живой адрес.

## 2. Что учтено из твоих правок

| Правка | Как легло в план |
|---|---|
| Беседы — один экран, разный источник | отдельного «чатов телеграма» и «табов агента» нет: одна модель беседы, два источника |
| Чтение базы — через Mirage | свой инструмент чтения не пишем: сессия поднимается с рабочей областью Mirage, база смонтирована на чтение |
| Очередь обязательна | bunqueue и процесс-брокер стоят в E0, до всякой логики |
| Миниаппы — спрайты сразу | публикация сразу в спрайт, не в каталог |
| Поток — вебсокеты | комната на беседу; SSE нет нигде |
| Модель | `deepseek-4.1-flash` через `xsai` |
| Домен | всё под `erodionov.com`; сейчас локальная машина |
| Токен бота | есть; в файлы не пишу, только в `.env.local` вне репозитория |

## 3. Одна модель беседы

Это ядро всего. Что бы ни случилось — сообщение из телеграма или ответ агента — это одна и та же
запись в одном и том же месте.

```
ctx.conversations(id, source, external_id, title, agent, created_at, last_message_at)
   source: telegram | agent
ctx.messages(id, conversation_id, role, author_name, text, sent_at, external_id, raw jsonb)
```

- Телеграмный чат заводит беседу с `source=tg`; вебхук кладёт сообщения в `ctx.messages`.
- Сессия агента заводит беседу с `source=agent`, связанную с ключом сессии gentic.
- Панель читает `ctx.conversations` и `ctx.messages` — ей всё равно, откуда пришло.
- Агент читает то же самое через Mirage. Один стол, одна правда.

**Где это лежит:** в базе компании. В ядре — только реестр (какая компания, какая сессия, какой ключ).
Копий нет: сообщение пишется один раз.

## 4. Решения по умолчанию

| Вопрос | Решение |
|---|---|
| Очередь | bunqueue: брокер отдельным процессом, три задачи — `msg.ingest`, `app.build`, `db.provision` |
| Вебхук | маршрут в нашем API; принял — ответил телеграму, работу отдал в очередь |
| Поток | вебсокет-комната на беседу: браузер ↔ наш API, наш API ↔ gentic |
| Чтение базы | Mirage, монтирование на чтение, профиль на агента |
| Запись в базу | через наш инструмент и очередь согласий (полноценно — 0.2) |
| Миниаппы | спрайт на апп, статика внутри |
| Токен миниаппа | выдан при публикации, только чтение представлений |
| Дизайн | дефолтный shadcn, ни одной своей темы |
| SGR | `xsai` + zod: модель заполняет схему, вердикт выносит код |
| Локально | api :8787, web :5173, миниаппы на `*.apps.localtest.me` (резолвится в 127.0.0.1) |

## 5. Что не входит в 0.1

квоты, биллинг, письма с инвайтами (показываем ссылку для копирования), второй язык интерфейса.

## 6. Этапы

### E0. Каркас

- Монорепо из шаблона shadcn (`--preset beqC8T2G --template react-router --monorepo --pointer`).
- Области: `apps/api` (Hono + `Bun.serve` + вебсокеты), `apps/worker` (bunqueue), `packages/db` (drizzle + postgres-js), `packages/llm` (xsai + SGR), `packages/core` (чистые функции).
- Брокер bunqueue отдельным процессом; три задачи-заглушки.
- `.env.local` вне репозитория: токен бота, ключ модели, строка подключения.
- Проверка: `bun run dev` поднимает api, web, брокер и воркер; `curl localhost:8787/health` отвечает.

### E1. Онбординг и выписка базы

- `/onboarding` — чистая функция шагов в `packages/core`.
- Четыре вопроса: название, чем занимается, кому инвайты, где коммуникации.
- После «чем занимается» — `xsai` + zod со схемой `CompanyProposal { industry, entities[], departments[], use_cases[] }`. Показываем списком, владелец подтверждает.
- `POST /v1/companies`, `POST /v1/companies/:id/database` → задача `db.provision`: `CREATE DATABASE`, три роли, схемы `app` и `ctx`, таблицы из предложения, журнал миграций.
- Проверка: под ролью арендатора вижу таблицы; агентская роль читает `ctx` и не пишет.

### E2. Беседы (телеграм + агент — один экран)

- Вебхук: `POST /v1/ingest/telegram` — проверка секрета, ответ сразу, работа задачей `msg.ingest`, которая заводит беседу и кладёт сообщение.
- Экран «Беседы»: список слева, лента справа, дефолтные компоненты shadcn. Телеграмный источник — только входящие.
- Проверка: пишу в телеграме — сообщение в панели.

### E3. Сессия агента и поток

- gentic: ветка в `Bun.serve` до проверки `/tg/`, комната на вебсокете, два эффекта (`emit`, `closeStream`), четыре события (открыть, закрыть, вопрос, стоп), ключ сессии с отрицательным `chatId`.
- api: `POST /v1/ask` открывает сессию, отдаёт её в беседу; `WS /v1/rooms/:conversationId` — комната наружу.
- web: беседа агента получает поле ввода, ответ идёт потоком.
- Проверка: пишу вопрос — ответ идёт стримом; перезагружаю страницу — история на месте из `ctx.messages`.

### E4. Чтение базы агентом

- Сессия поднимается с рабочей областью Mirage: база компании смонтирована на чтение, профиль привязан к агенту.
- Учётные данные выдаёт `POST /v1/agent/db-credential` на роль чтения, срок минуты.
- Проверка: «дай статус по проектам» — отчёт приходит, в логе видно чтение только своей базы.

### E5. Канбан на спрайте

- Инструмент `publish_app`: принимает файлы, поднимает спрайт, отдаёт адрес, пишет запись в реестр аппов с токеном на чтение.
- Данные миниаппу: одно представление, только чтение, только своя компания.
- Проверка: «собери канбан» → открываю адрес → доска рисуется из моей базы.

### E6. Канон SGR

- Скилл в `~/dev/imevro-skills/skills/sgr/`: техника, когда применять, как писать схему, почему вердикт выносит код, чем проверять. Опирается на четыре существующих скилла про валидатор.
- В `packages/llm`: `sgr(schema, input)` плюс ограниченный цикл переспроса.

## 7. Готово и нужно

- Токен бота — есть, лежит только в `.env.local`. Он светился в переписке: перед продакшеном перевыпустить.
- Модель — `deepseek-4.1-flash`, `xsai`.
- Домен — `erodionov.com`, зона уже на Cloudflare.
- Машина — локальная.
- От тебя нужно: Apple Services ID, ключ и адрес возврата — или старт на входе по почте, Apple следом.

## 8. Риски

| Риск | Ответ |
|---|---|
| Транспорт gentic — самый большой кусок | делать сразу после бесед, остальное от него не зависит |
| Комната на вебсокете внутри gentic | реестр комнат живёт в `bot.ts` рядом с картой процессов (там разрешена изменяемость); в ядре только счётчики |
| Apple | можно начать с почты |
| Подстановочный адрес для аппов | зона на Cloudflare, сертификат по проверке DNS-01; локально хватает `localtest.me` |
| Бот в группе не видит сообщений | бот должен быть админом либо с выключенным приватным режимом |
